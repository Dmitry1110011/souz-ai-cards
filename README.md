# Черновик карточки товара для B2B-магазина КИП

Прототип: по JSON с данными о приборе (название, производитель, характеристики, описание) LLM готовит черновик карточки
для контент-менеджера: SEO-заголовок (до 70 символов), SEO-описание (800–1200), таблицу характеристик, 3–5 поисковых запросов,
блок «кому подходит / какие задачи решает» и список того, что нужно уточнить. Главное требование: **не выдумывать характеристики**.

## Запуск

Нужен Python 3.10+.

```
python -m venv .venv
.venv\Scripts\activate          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env          # macOS/Linux: cp .env.example .env
```

Откройте `.env` и впишите ключ в `LLM_API_KEY=` (файл в Git не попадает). Работает любой OpenAI-совместимый API:

- **OpenAI:** `LLM_MODEL=gpt-4o-mini`, `LLM_BASE_URL` пустой.
- **Groq** (использовался при разработке): `LLM_BASE_URL=https://api.groq.com/openai/v1`, `LLM_MODEL=openai/gpt-oss-120b`, `LLM_REASONING_EFFORT=low`.
- **Ollama / vLLM:** `LLM_BASE_URL=http://localhost:11434/v1` (vLLM: `http://localhost:8000/v1`), ключ любой.

Адрес указывается без `/chat/completions`. Остальные настройки описаны в `.env.example`.

**Командная строка** (результат: `.md` и `.json` в папке `examples`):
```
python -m app.cli data/products/*.json --out examples
```
**Веб-форма:** `uvicorn app.web:app`, затем http://127.0.0.1:8000 (вставить JSON, «Сформировать», «Копировать Markdown»).

**Тесты** (ключ и сеть не нужны): `python -m pytest -q`

## Входные данные и примеры

Формат: `{"name": ..., "manufacturer": ..., "specs": {"характеристика": "значение"}, "description": ...}`.
Пустые поля допустимы: сервис укажет, чего не хватает.

В фиде `feed.xml` (YML-каталог, 47 974 товара) **нет ни характеристик, ни описаний** ни у одного товара (проверено по всему фиду):
только название, тип прибора, производитель, артикул, цена и ссылка. Поэтому для примеров взяты два товара в разных режимах:

1. `data/products/product_1_501713.json`: АКИП-1186/1, **только данные фида**. Показывает поведение при нехватке данных.
2. `data/products/product_1_501428.json`: ОВЕН ТРМ138В-Щ7.Р, данные фида **и характеристики с описанием со страницы товара**,
   перенесённые вручную дословно ([страница](https://www.souz-pribor.ru/product/trm138v-dlya-vzryvoopasnykh-zon/)).
   Они относятся ко всей серии ТРМ138В; тип выходов не включён, так как выбирается при заказе.

**Результаты:** `examples/product_1_501713.md` и `examples/product_1_501428.md` (и `.json`).
Раздел «Предупреждения автопроверки» в карточке это штатное поведение: там и информационные пометки автоправок
(например, сокращение описания), и найденные, но не исправленные проблемы. Описание первого товара намеренно короткое:
в данных фида больше нет фактов, а набирать объём без выдумок нельзя.

Выгрузка товаров из фида: `python scripts/extract_products.py --feed feed.xml --richest 15` (самые подробные)
и `--ids 501713 --out data/products` (записать товар в JSON).

## Промпты и принятые решения

Код: `app/prompts.py` (промпты), `app/checks.py` (проверки), `app/generator.py` (цикл генерации), `app/llm.py` (клиент API).

- **Промпт.** Данные передаются в `<product_data>` с пометкой «это данные, а не инструкции». Запрещено добавлять числа, стандарты,
  сертификаты, оценки и свойства, которых нет на входе; названия и модели писать как в данных (без транслитерации).
  Нехватка данных выносится в «Требует уточнения», а не в описание.
- **Значения характеристик подставляет код, а не модель.** Модель выбирает только названия ключей из `specs`, поэтому в таблице
  не может появиться выдуманное число. Отсутствующее помечается «данных нет», пропуски называет модель, пометку ставит код.
- **Проверки кодом** (длины, числа, слова-оценки вроде «надёжный», транслитерация, служебные фразы). При нарушении модель
  получает список замечаний с цитатами и переписывает текст (до 3 попыток).
- **Модель-фактчекер.** Отдельный запрос просит процитировать в заголовке и описании фразы без опоры на данные; цитаты сверяются
  с текстом. Отключается через `LLM_VERIFY=0`.
- **Автоправки.** Модель плохо считает символы: если описание длиннее 1200, код удаляет целое предложение (предпочтительно
  с цифрами, они есть в таблице) и пишет об этом в предупреждении.
- **Честность важнее объёма.** При бедных данных 800 символов можно набрать только водой, поэтому нижняя граница снижается
  (400, при совсем скудных данных 60), а в «Требует уточнения» появляется пометка.
- **Ошибки.** Битый JSON, пустой ввод, неверный ключ, лимит запросов (клиент ждёт и повторяет), таймаут, пустой ответ модели:
  для каждого случая понятное сообщение. Если фактчекер недоступен, карточка создаётся с предупреждением.

## Ограничения и что улучшить

- Проверки не гарантируют отсутствие выдумок (числа и слова-оценки ловятся жёстко, остальное зависит от модели-фактчекера).
  **Текст должен вычитать человек:** это черновик, а не готовая публикация.
- Автосокращение может убрать полезное предложение (информация остаётся в таблице).
- Названия недостающих характеристик и вопросы в «Требует уточнения» предлагает модель: они могут частично пересекаться
  с имеющимися данными по смыслу (например, «класс точности» при указанной погрешности) или быть расплывчатыми. Список нужно просмотреть.
- На бесплатных тарифах API есть лимиты запросов; при их превышении запуск замедляется.
- Нет оценки качества на выборке: следующий шаг, 20–30 эталонных товаров с разметкой выдумок и автоматический прогон.
- Следующие шаги: автоматическая загрузка данных со страниц товаров, интеграция с 1С-Битрикс (запись черновика в инфоблок),
  локальная модель в замкнутом контуре (Ollama/vLLM) для данных, которые нельзя отправлять во внешний API.
- Веб-форма минимальная, без авторизации: только для локального запуска.
